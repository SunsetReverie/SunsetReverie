## 二、问题清单

### P0（必须修，否则实现会撞车）

#### P0-1 行数阈值存在两套互斥标准

| 位置 | 当前表述 |
| --- | --- |
| 1.4 设计公理 | 核心代码总行数 **≤ 25,000 行**（不含注释） |
| 1.8 KPI | 核心代码总行数（不含注释/空行）**≤ 25,000** |
| 3.4 度量表 | 内核 ≤ 1,500 / 上限 2,000；组件 ≤ 12,000 / 上限 15,000 |
| 4.1 目录树 | `core/` ≤ 2,000 行；`components/` 合计 ≤ 15,000 |
| 附录 G | Kernel ≤ 2k 行 |

**问题**：25,000 ≠ 2,000 + 15,000 = 17,000。前两处是批次一之前的旧标准，未随 3.4 的双阈值同步。

**建议**：1.4 与 1.8 改为「内核 ≤ 2,000 行、组件合计 ≤ 15,000 行」，与 3.4 对齐，并注明"目标值/上限值见 3.4"。

#### P0-2 错误码表缺 6 个正文已引用的码

正文引用但 14.2 表未登记：

| 码 | 引用位置 | 含义 |
| --- | --- | --- |
| `20010` | 6.8 四重校验（3 处） | 跨域凭证（token 与域不匹配） |
| `20011` | 7.10.5 签名 URL | 链接已失效 |
| `30007` | 7.11.1 幂等 | 缺少 `Idempotency-Key` |
| `40008` | 3.5 / 6.3.2 / 6.3.4 | 未匹配任何 API 域 |
| `40009` | 7.11.1 幂等 | 相同幂等键处理中 |
| `40010` | 7.11.2 乐观锁 | 数据已被他人修改 |

**影响**：实现时不知道这些码的常量名与默认消息，也无法写进错误码注册表。

#### P0-3 错误码常量命名与 4.4 规范矛盾

- 4.4 命名规范（批次三已改）：枚举成员用 **PascalCase**（`ErrorCode::ValidationFailed`）
- 附录 B 枚举定义：`case ValidationFailed = 30001;` ✅
- **14.2 表**：32 行全部是全大写（`VALIDATION_FAILED`、`ROUTE_NOT_FOUND`…）❌

**影响**：同一份文档里同一个码有两种写法，实现者会二选一，选错就与规范冲突。

### P1（应修，影响一致性与可用性）

#### P1-1 附录 A 配置项全表缺 `api.routing_mode`

6.4 与 6.6.2 已把 `routing_mode` 作为核心配置项，附录 A（配置项全表）未登记。

#### P1-2 12.4 命令表缺 3 条正文已用命令

| 命令 | 正文出现位置 | 用途 |
| --- | --- | --- |
| `sr lint:architecture` | 12.5.10、16.1、16.3.1、附录 H（4 处） | ARCH-1～ARCH-8 架构测试 |
| `sr upload:prune` | 7.10.4 | 清理过期分片 |
| `sr docs:build` | 17.3 | 构建文档站 |

#### P1-3 `API域` 缺少空格（1 处）

与全文 42 处「API 域」不一致。

#### P1-4 `sr new --domains` 生成的骨架会启动失败

- `routing_mode` 默认 `single`（6.6.2）
- `single` 模式下存在 `routes/{domain}/` 子目录 → 抛 `RoutingModeException`（RM-2）
- 但 12.5.1 说 `sr new --domains=...` 会生成 `routes/{domain}/v1.php`（目录结构）

**结果**：按文档走一遍，`sr new --domains=admin,web` 后第一次启动就报 RM-2。

**建议**：`sr new --domains` 自动把 `routing_mode` 写为 `directory`，并在 12.5.1 明确。

#### P1-5 内核行数表述在 4.1 只写上限

4.1 目录树与判据表只写 `≤ 2,000`，3.4 是「目标 1,500 / 上限 2,000」。建议在 4.1 加注"目标值见 3.4"，避免读者以为 2,000 就是目标。
