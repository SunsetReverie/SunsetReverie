## 二、按优先级的执行顺序

### P0 — 能直接发现真问题（建议立刻做）

#### [ ] P0-1 PHPStan level 6 → 8

**为什么排第一**：最近三轮自己写出并踩到的 5 个 bug，**4 个 PHPStan 能提前拦住**。

| 已发生的 bug | PHPStan 能否拦截 |
| --- | --- |
| `insertGetId()` 声明 int 实参 string | ✅ |
| `sum()` 声明 `int\|float` 实参 string | ✅ |
| `ConnectionException` 构造参数数量不符 | ✅ |
| `unique()` 忽略多余参数 | ✅ |
| `Auth::id()` 恒为 null | ❌（逻辑错误，靠测试） |

**怎么做**（**不引入 composer**，用官方单文件 phar）

```bash
# 1. 下载（约 30MB，单文件，无依赖）
curl -L -o phpstan.phar \
  https://github.com/phpstan/phpstan/releases/latest/download/phpstan.phar

# 若 GitHub 慢，可到 https://github.com/phpstan/phpstan/releases 手动选版本下载
# 文件校验：能正常跑 --version 即完整

chmod +x phpstan.phar
php phpstan.phar --version

# 2. 配置：phpstan.neon 已存在（仓库内），无需再建

# 3. 跑
php phpstan.phar analyse --memory-limit=1G --no-progress
```

> **为什么不用 composer**：本项目卖点是「运行时零依赖」，虽然 composer 只装 dev 工具、
> 不会影响运行，但引入 `composer.json` + `vendor/` 会让「零依赖」这句话变得需要解释。
> 单文件 phar 不落地任何目录结构，`git status` 也不会多出东西（`.gitignore` 已忽略 `phpstan.phar`）。

> 若要放进 PATH 全局使用：`mv phpstan.phar ~/.local/bin/phpstan && chmod +x ~/.local/bin/phpstan`



**验收标准**
- `php phpstan.phar analyse` 退出码 0
- `phpstan.neon` 里 `level: 8`
- 过程中发现的问题全部修复或在 `ignoreErrors` 里写明理由

**注意**
- `.gitignore` 已忽略 `phpstan.phar`（避免误提交 30MB 二进制）
- level 从 6 起步：直接上 8 会一次报上千条，分批修更可控

#### [ ] P0-2 补齐架构测试 ARCH-5 ～ ARCH-8

**为什么**：文档 16.3.1 承诺 8 项检查，实际只实现 4 项。这是**文档与实现不一致**，和之前修的「39 条错误码只实现 18 条」是同一类问题。

**缺的 4 项**（文档 16.3.1 的定义，需要先核对原文确认语义）：

| 编号 | 大致语义 |
| --- | --- |
| ARCH-5 | 组件内不得依赖 `Foundation`（组件不应反向依赖内核组装层） |
| ARCH-6 | 控制器不得直接使用 `Connection`（应走领域服务） |
| ARCH-7 | 领域服务不得引用 `Http`（业务逻辑与协议解耦） |
| ARCH-8 | 见文档 16.3.1 原文 |

**怎么做**
1. 先读文档 16.3.1 确认 8 项的精确定义
2. 在 `core/Console/Lint/ArchitectureChecker.php` 里补实现（现有 4 项是类似的 AST/文本扫描）
3. 跑 `php bin/sr lint:architecture`，**预期会报出真实违规**——现有代码不一定全部合规

**验收标准**
- `lint:architecture` 输出 8 项全 OK
- 若必须加白名单，注释写明理由（参考 ARCH-3 的 `ALLOWED_COMPONENT_DEPS`）

### P1 — 让别人能跑起来

#### [ ] P1-1 GitHub Actions CI

**为什么**：没有 CI 时「别人 clone 下来能不能跑」是未知数。已知的跨版本差异实例：
- PHP 8.5 的 `fputcsv()` 要求显式 `$escape`
- PHP 8.5 的 `imagedestroy()` 标记废弃

**怎么做**

```yaml
# .github/workflows/test.yml
name: test

on:
  push:
  pull_request:

jobs:
  test:
    runs-on: ubuntu-latest
    strategy:
      fail-fast: false
      matrix:
        php: ['8.3', '8.4', '8.5']
    steps:
      - uses: actions/checkout@v4

      - uses: shivammathur/setup-php@v2
        with:
          php-version: ${{ matrix.php }}
          extensions: pdo, pdo_mysql, pdo_pgsql, pdo_sqlite, mbstring, json, fileinfo, openssl, gd
          coverage: pcov

      - run: composer install --no-interaction --prefer-dist

      - name: 单元测试（SQLite）
        run: php tests/run.php

      - name: 架构检查
        run: php bin/sr lint:architecture

      - name: PHPStan
        run: vendor/bin/phpstan analyse --memory-limit=1G --no-progress

  # 三库契约测试：用 service 容器
  database:
    runs-on: ubuntu-latest
    services:
      mysql:
        image: mysql:8.0
        env:
          MYSQL_ROOT_PASSWORD: root
          MYSQL_DATABASE: sr_test
        ports: ['3306:3306']
        options: >-
          --health-cmd="mysqladmin ping -h 127.0.0.1 -uroot -proot"
          --health-interval=10s --health-timeout=5s --health-retries=10
      postgres:
        image: postgres:16
        env:
          POSTGRES_PASSWORD: postgres
          POSTGRES_DB: sr_test
        ports: ['5432:5432']
        options: >-
          --health-cmd=pg_isready
          --health-interval=10s --health-timeout=5s --health-retries=10
    steps:
      - uses: actions/checkout@v4
      - uses: shivammathur/setup-php@v2
        with:
          php-version: '8.4'
          extensions: pdo, pdo_mysql, pdo_pgsql
      - run: composer install --no-interaction
      # 门禁 2 要求「三库 × 三缓存契约测试全绿」，
      # 这里需要把 tests/Integration 里的方言测试真正接进 CI
      - run: php tests/run.php --filter=Integration
```

**验收标准**
- 3 个 PHP 版本的 job 全绿
- 数据库 job 让 PostgreSQL 方言测试在 CI 里真实执行（目前只有本机手工验证过）

### P2 — 质量度量

#### [ ] P2-1 覆盖率 ≥ 80%

**为什么**：本机连覆盖率工具都没装，等于「不知道哪里没测」。Imagick 驱动写完一直没运行，就是这类问题。

**怎么做**

```bash
# 二选一
pecl install pcov          # 轻量，推荐
# 或
pecl install xdebug

php -d pcov.enabled=1 -r '...'
```

需要给 `tests/run.php` 加 `--coverage` 支持（自研测试框架，得自己统计），或改用 `phpunit` 跑同一批测试类。

**务实判断**：自研框架要自己做覆盖率统计成本不低。**更简单的路是**：
1. 临时用 `pcov` + 一个脚本统计「哪些文件被 `require` 过」
2. 或用 `php -d pcov.enabled=1 tests/run.php` 配合 `pcov\start()/stop()` 手写统计

**验收标准**：`docs/coverage/` 下有报告，行覆盖率 ≥ 80%，且报告能指出未覆盖的文件。

#### [ ] P2-2 三库契约测试接入自动化（门禁 2）

**为什么**：目前 SQLite 在测试套件里跑，MySQL / PostgreSQL 靠我手工在临时项目验证。**手工验证过一次不等于可持续**——下次改方言代码没人会发现回归。

**怎么做**
1. `tests/run.php` 支持通过环境变量切换连接（`SR_TEST_DB=mysql|pgsql|sqlite`）
2. 现有 `tests/Integration/PostgresDialectTest.php` 的模式（检测到环境就跳过）保留，但要让它**在 CI 里真的执行**
3. 抽出「方言契约」：建表、类型映射、事务、批量插入、聚合——同一套断言在三种数据库上跑

**验收标准**：CI 的 database job 里，三种数据库各跑一遍同一批契约断言，全绿。

### P3 — 可以放到 v1.1

#### [ ] P3-1 性能基准

**为什么放最后**：本机数字不可复现（温控、负载、PHP 版本都会影响），写进 `docs/benchmarks/` 的参考价值有限。

**若要做**：需要固定环境（CI 的固定规格 runner），并明确标注「仅供参考，非 SLA」。

**建议指标**：`/health` 的 QPS、简单列表接口的 P99、批量插入 1000 条的耗时、2 万行 CSV 导出的峰值内存（已知 < 1 KB）。

#### [ ] P3-2 跨平台验证（Linux / Windows）

Linux 可在 CI 里覆盖（Ubuntu runner）；Windows 需要专门的 runner，成本较高。

**最小可做**：CI 里加一个 `windows-latest` job 跑单元测试，能发现路径分隔符、文件权限之类的问题。

#### [ ] P3-3 安全自查清单（门禁 9）

需要先读文档 11.6 的原文，逐条核对。已知需要覆盖：
- SQL 注入（`assertIdentifier` 白名单、`selectRaw` 的边界）
- 越权（`where('user_id', ...)` 是否每处都有）
- 上传（扩展名 + MIME 双检、`/uploads/` 禁止执行 PHP）
- Token 域绑定（`web` token 不能访问 `admin`）
